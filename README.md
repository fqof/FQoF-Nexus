## 🌟 Основные возможности

* **3 режима маршрутизации:**
  * **🛡️ TUN:** Полное туннелирование 100% сетевого трафика системы через виртуальный сетевой драйвер Wintun.
  * **🌐 Системный:** Управление системным прокси Windows (WinINet) для браузеров и системных служб с умным автообходом российских ресурсов.
  * **🔌 Локальный:** Локальные порты SOCKS5 (`127.0.0.1:10808`) и HTTP (`127.0.0.1:10809`) для ручной настройки любых программ (Telegram, браузеры, игры).
* **Профили маскировки:**
  * **🕶️ ТСПУ Ghost:** Режим максимальной скрытности трафика с постквантовой криптографией и разделением потоков XHTTP.
  * **⚡ REALITY:** Маскировка под легитимные TLS-рукопожатия доверенных мировых ресурсов.
* **Мониторинг в реальном времени:**
  * Точный расчет входящей и исходящей скорости соединения (KB/s, MB/s) во всех трех режимах.
  * Непрерывный опрос сетевой задержки (живой пинг) до сервера.
* **Изоляция приложений:** Запуск выборочных игр и программ в изолированном TUN-окружении.
* **Минималистичный интерфейс:** Чистый светлый дизайн, быстрый выбор пресетов прямо на главной странице и удобное сворачивание в системный трей.

## ⚙️ Требования к VLESS-серверу

Для полноценной работы приложения требуется настроенный сервер **Xray-core** со следующими протоколами:

1. **VLESS + XHTTP (для режима «ТСПУ Ghost»):**
   * Транспорт: `xhttp` (SplitHTTP через HTTP/2 или HTTP/3).
   * Безопасность: `tls` на стандартном порту `443`.
   * Шифрование: поддержка постквантового ключа `mlkem768x25519plus`.
2. **VLESS + REALITY (для альтернативного режима «REALITY»):**
   * Транспорт: `tcp`.
   * Безопасность: `reality`.
   * Flow: `xtls-rprx-vision`.
   * Маскировочный домен (SNI), например: `api.weatherapi.com`, `apple.com` или ресурсы Microsoft.
   * Наличие пары ключей Reality (`reality_public_key`, `reality_short_id`).
3. **Порт DNS:** Локальный или удаленный защищенный DNS-резолвер (порт `53`).

## 🔐 Настройка подключения (`secrets.json`)

Все параметры серверов, ключи шифрования и ссылки на внешние ресурсы вынесены в единый файл конфигурации `secrets.json`.

> ⚠️ **Важно:** Файл `secrets.json` включен в `.gitignore` и никогда не попадет в публичный репозиторий. Для шаблона используйте `secrets.example.json`.

### Пример заполнения `secrets.json`:
Создайте файл `secrets.json` в корневой папке проекта со следующим содержимым:

```json
{
  "server": {
    "host": "your-server-ip-or-domain.com",
    "port": 443,
    "server_ip1": "198.51.100.1",
    "server_ip2": "198.51.100.2",
    "uuid": "00000000-0000-0000-0000-000000000000",
    "user": "your_username",
    "pass": "your_strong_password",
    "sni": "p.your-domain.com",
    "path": "/api/v1/telemetry",
    "reality_sni": "api.weatherapi.com",
    "reality_public_key": "your_reality_public_key",
    "reality_short_id": "your_short_id",
    "post_quantum_encryption": "mlkem768x25519plus.native.0rtt.your_pq_key",
    "remote_dns_host": "172.29.172.254",
    "remote_dns_port": 53
  },
  "api_base": "https://your-domain.com/api/v1",
  "links": {
    "telegram": "https://t.me/your_bot",
    "website": "https://your-site.com"
  }
}
```

### Где указать свои Telegram и Сайт:
В блоке `"links"` файла `secrets.json`:
* `"telegram"` — ссылка на вашего Telegram-бота или канал (кнопка в левом нижнем углу интерфейса).
* `"website"` — ссылка на ваш сайт или личный кабинет (кнопка в правом нижнем углу интерфейса).

## 🎛️ Изменение названия сетевого адаптера TUN

По умолчанию виртуальный Wintun-адаптер создается с именем **`FQoF`**.

Если вы хотите изменить имя сетевого адаптера на своё (например, `MyVPN`):
1. **В скрипте PowerShell** (`bin/tun_helper.ps1`):
   * Найдите параметр:
     ```powershell
     [Parameter(Position=1)]
     [string]$TunDev = "FQoF",
     ```
   * Замените `"FQoF"` на желаемое имя.
2. **В batch-скрипте** (`scripts/tun_helper.bat`):
   * Найдите строку:
     ```cmd
     if "%TUN_DEV%"=="" set TUN_DEV=FQoF
     ```
   * Замените `FQoF` на ваше имя.
3. **В модуле бэкенда** (`gui/backend.py`):
   * В методах опроса адаптера (`_query_tun_adapter_stats` и настройки Wintun) укажите имя вашего адаптера.

## 👤 Создание и синхронизация профиля клиента

В клиенте реализована система автоматической регистрации устройств через **ProfileManager**.

### Как это работает:
1. **Определение HWID:** При старте клиент считывает постоянный аппаратный идентификатор машины из реестра Windows:
   `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid`
2. **Синхронизация с сервером:** Фоновый поток отправляет POST-запрос на эндпоинт `api_base/profile`:
   * Передаются `hwid`, имя компьютера и версия ОС.
   * Серверная служба (`scripts/server_profile_daemon.py`) проверяет HWID в SQLite-базе данных:
     * Если устройство новое — генерируется новый UUID и добавляется в конфигурацию Xray на сервере.
     * Если устройство уже зарегистрировано — возвращается ранее назначенный UUID.
3. **Кэширование:** Назначенный UUID сохраняется локально в:
   `%LOCALAPPDATA%\FQoF_Nexus\profile.json`
   При отсутствии интернета клиент использует кэшированный UUID.

### Что нужно сделать для работы профилей:
* **Если серверный демон не нужен:**
  * Вы можете не поднимать службу регистрации — клиент просто будет использовать статичный UUID, указанный в `secrets.json`.

## 🛠️ Сборка автономного исполняемого файла (.exe)

Для сборки проекта в единый бинарник используется PyInstaller:

1. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
2. Убедитесь, что файл `secrets.json` находится в корневой папке.
3. Запустите скрипт сборки:
   ```bash
   python build_exe.py
   ```
4. Готовый исполняемый файл будет помещен в папку `dist/FQoF_Nexus.exe` (и продублирован в корень проекта).
   * Файл автоматически запрашивает права Администратора (`--uac-admin`) для настройки сетевого адаптера Wintun.
   * Все бинарники (Xray, Sing-box, Wintun) и конфиг упаковываются внутрь одного `.exe`.
